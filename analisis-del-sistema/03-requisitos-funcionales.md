# Requisitos funcionales

## 1. Introducción

Los requisitos funcionales describen las funciones que el sistema debe proporcionar para satisfacer las necesidades identificadas en las historias de usuario.

---

## 2. Requisitos funcionales del Marketplace

| ID | Requisito funcional |
|---|---|
| RF-01 | El sistema debe permitir buscar productos mediante criterios de búsqueda. |
| RF-02 | El sistema debe permitir consultar la información, precio y disponibilidad de los productos. |
| RF-03 | El sistema debe permitir agregar productos al carrito de compras. |
| RF-04 | El sistema debe permitir modificar y eliminar productos del carrito de compras. |
| RF-05 | El sistema debe permitir generar un pedido a partir de los productos seleccionados en el carrito. |
| RF-06 | El sistema debe permitir consultar los pedidos realizados y su estado. |
| RF-07 | El sistema debe permitir a los sellers registrar productos en el marketplace. |
| RF-08 | El sistema debe permitir a los sellers actualizar la información de sus productos. |
| RF-09 | El sistema debe permitir a los sellers actualizar precios y stock de sus productos. |
| RF-10 | El sistema debe permitir a los sellers consultar los pedidos correspondientes a sus productos. |
| RF-11 | El sistema debe permitir a los sellers consultar información relacionada con sus ventas. |
| RF-12 | El sistema debe permitir al administrador gestionar los usuarios de la plataforma. |
| RF-13 | El sistema debe permitir al administrador registrar, actualizar y desactivar sellers. |
| RF-14 | El sistema debe permitir al administrador supervisar los productos publicados en el marketplace. |
| RF-15 | El sistema debe permitir al administrador registrar, actualizar y eliminar categorías de productos. |
| RF-16 | El sistema debe permitir al administrador consultar y supervisar los pedidos realizados en la plataforma. |

## 4. Resumen

Los requisitos funcionales identificados definen las principales operaciones que deberá proporcionar el marketplace para los clientes, sellers y administradores.

Estos requisitos servirán posteriormente como base para identificar los atributos de calidad, restricciones y drivers arquitectónicos del sistema.
